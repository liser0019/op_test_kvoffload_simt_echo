# ABD512 热路径五因素与组合实验

本分支以冻结的 `joint_refine_abd_512` 为算法基础，正常SIMT保持512线程，原逐行回退1024线程。新增五个因素的32种配置（含control），再加分类SIMD单独版、miss SIMD单独版，共34个新配置。保留ABCDF、bounds、冻结ABD、冻结BD四路，因此默认38路。

所有新配置仍包含旧refine的A+B+D；本轮字母A/B/C/D/E是新因素，与历史同名字母无关。公开ID159..190对应五因素bit组合，191/192是两个单独SIMD配置。新候选尚未在本机执行CANN/Bisheng编译或NPU验证。

## 五个因素

| 因素 | 改动 | 边界 |
|---|---|---|
| A：4KiB UB负过滤 | 对unique中token按低15位建立32768-bit过滤器。resident对应bit为0时跳过二分，为1仍精确二分 | 只在热路径、UB scratch、capacity>=1024时启用；复用尚未使用的partition前1024个int32。冲突只能增加查找，不能丢命中。冷启动、GM及小容量保持原查找 |
| B：SIMD热压缩 | SIMD稳定生成evict列表、反向hit列表、miss排名和分配scratch。分类与miss在同一SIMD VF内完成 | 只在UB使用；SIMT保留resident查询与atomic owner，容量检查通过后才提交。组合VF显式LocalMemBar保证partition写后读、flags生命周期切换 |
| C：归并包扩容 | 对2048/4096生产形状、原本已在UB的布局，把scratch扩大至既有112KiB行上限，增加归并输入/输出区 | 不改112KiB上限，不将GM形状强行转UB。生产MTP3每包准备量由3072提高到4080条记录；实际MrgSort轮数依数据分布决定。MTP0/1分配也可能变化，六工况均需观察 |
| D：失效判断复用 | 第一次resident读取时将token>=stable的物理slot标记带入partition；容量检查后按标记清理，免除第二次slotToToken读取 | 延续原LRU必须为slot排列的输入契约。标记只存在scratch，LRU/currentSlots/missSlots写出前去除标记；原越界LRU回退保留，持久写入前不修改缓存 |
| E：尺寸特化 | 同一个SIMT VF入口内，对TopK2048/capacity4096实例化常量尺寸Stage；其他形状走通用Stage | 不硬编码命中率、token、miss、请求或可见长度。全局偏移仍64位；不引入外层双VF运行时启动结构 |

A复用的是归并结束后的临时区，因此不需为位图另加常驻4KiB；它与C采用不同生命周期。B的新SIMD函数使用寄存器prefix和Scatter进行稳定压缩，不依赖Squeeze的AR隐式状态。它必须处理尾块、全hit、全evict、空union、重复resident及容量不足，不是只筛出有效元素就结束。

两个额外配置：

- `joint_hot_part_512`：仅分类使用SIMD，miss保留SIMT。
- `joint_hot_miss_512`：仅miss使用SIMD，分类保留SIMT。

它们可区分SIMD各部分收益与阶段交接成本。B组合版的分类与miss放在同一个SIMD VF中，中间不回Scalar。

`joint_hot_base_512`关闭本轮五个因素，用于观察新代码组织/编译变化。最终仍与冻结ABD比较，不能只因快于control就认定取得收益。

## 计算代码集中在哪里

新算法全部集中在 `csrc/joint_variants/hot_plan_impl.h`，便于顺序阅读：

1. 因素定义、原Scan及有序查找；
2. `SortedStage`：单行、打包、热查询、SIMT回退收尾，及6/7/8/9分阶段入口；
3. `SortedStageVf`：同一入口内的生产尺寸/通用形状路由；
4. 原D的 `RefineUniqueMapVf`：多行归并后的SIMD编号；
5. `HotCompactVf`：本轮SIMD分类、miss压缩与分配；
6. `SortedDirectBody`：MrgSort调度、热SIMD路径和旧路径选择。

不要求读多个新的计算头。原 `refine_stage.h`、`refine_simd.h`、`refine_controller.h`、`cold_finish.h` 和带页表ABCDF计算源码保留，作为冻结参考。代码行数增长来自独立实验副本和SIMD实现，文件拆分不对应额外kernel下发。

B的热执行顺序：SIMT查询resident → SIMD分类/分配scratch → SIMT提交。冷启动在SIMT查询入口直接执行原cold_finish，不运行热SIMD。GM使用原SIMT压缩；D的失效标记在合法LRU下同样可使用GM scratch。所有路径保留线程1发布rowModes的实验规避，底层原因仍未确认。

## 服务器一次执行

保留之前已验证的目录、共享库和结果，在新目录克隆。本示例使用逻辑卡0；如果实际用其他空闲卡，明确修改 `--device`，目录名称不能证明实际设备。

```bash
source /usr/local/Ascend/cann-9.1.0/set_env.sh
mkdir -p /workspace/single_op_test
cd /workspace/single_op_test
RUN_DIR=$(mktemp -d /workspace/single_op_test/abd_hot_XXXXXX)
git clone --single-branch --branch feat/abd512-hot-pipeline-sweep \
  https://github.com/liser0019/op_test_kvoffload_simt_echo.git "$RUN_DIR/src"
cd "$RUN_DIR/src"
git rev-parse HEAD | tee "$RUN_DIR/source_commit.txt"
export PYTHON=/usr/local/python3.11.10/bin/python3
bash scripts/test_hot_sweep.sh --device 0 \
  --output "$RUN_DIR/results" --temp-dir "$RUN_DIR/tmp"
```

CANN与Python路径按服务器实际环境调整，保留现有 `-O3` 及工具链选项。结果与临时目录须有空间；输出目录不能已存在。原始数据只留在服务器，不上传输入、失败现场、二进制或trace。

默认流程：

1. `--hot-only` 精简构建38路目标；仍生成并检查源码/库身份。
2. 全选实现的严格门禁：输入不变回归5次、冷/热、MTP0/1/3、重复query/resident、因果有效区间、非均匀组、并集溢出、自然GM、小容量、SIMD63/64/65边界、位图冲突与8步连续状态。
3. 全38路六工况初筛：warmup2、repeat5。
4. 每个工况取前2个新候选，取并集，始终保留ABCDF、bounds、冻结ABD、冻结BD、control；重新采集warmup10、repeat50。

初筛只用于入围；不混入正式样本。只有门禁通过才开始采集。若要全部正式计时，使用：

```bash
bash scripts/test_hot_sweep.sh --device 0 --full-confirm \
  --output "$RUN_DIR/all_formal" --temp-dir "$RUN_DIR/tmp"
```

若想先只测单点和两个SIMD单独版，可使用同一个入口缩小范围，保留五个参考：

```bash
bash scripts/test_hot_sweep.sh --device 0 --full-confirm \
  --implementations abcdf_pages joint_integrated_bounds_512 \
    joint_refine_abd_512 joint_refine_bd_512 joint_hot_base_512 \
    joint_hot_a_512 joint_hot_b_512 joint_hot_c_512 joint_hot_d_512 \
    joint_hot_e_512 joint_hot_part_512 joint_hot_miss_512 joint_hot_abcde_512 \
  --output "$RUN_DIR/subset" --temp-dir "$RUN_DIR/tmp"
```

已有本提交构建可加 `--skip-build`；仍做身份检查，不能复用其他分支库。`--describe-only`只打印配置，不初始化NPU。

## 输入与报告

沿用上一轮：32请求、TopK2048、capacity4096、max_token262144、block_size64、seed2026；MTP0/1/3对应32/64/128条query；cold_reset、full_cache_75pct、共同升序输入、overlap40。75%仍是首行的初始命中标签，后续行实际命中/miss不能按75%解释。

每次调用前恢复相同初态，污染scratch/输出，逐样本检查输入、缓存、逐位置currentSlots、LRU、miss有效前缀和完整尾部、保护区、模式及回退。连续状态门禁直接使用上一轮设备返回状态，不用golden覆盖。只测Plan，不计Transfer/SFA或接口端到端延时。

计时来自精确目标kernel的设备Duration(us)，严格检查样本数与轮换调用顺序，排除TensorMove及恢复拷贝。ACTIVE开始后仍记录1秒宿主等待，作为已有采集侧规避。

`report.md`列出正式P50/P95、样本数、当前实现/ABCDF、/bounds、/ABD、/BD、/control和共享/回退/单行组；比值小于1表示更快。`selection.json`保留初筛排名；采集子目录的 `capture_metadata.json`、`data_index.json`保存输入/设备/编译/库身份、实际miss/descriptor数、原始样本及CSV索引。

首次失败立即停止并保存日志/现场，不生成成功报告。只有退出码0、报告、COMPLETE.json齐全才算整轮成功。输出/临时目录空间与inode检查在初始化NPU前执行；阈值可配置，不预测准确trace大小。若显式使用 `/dev/shm`，需要自行转存。

## 本地验证边界

CPU语义模型和UBSan能检查计算、scratch布局、只读输入、保护区及控制流程，不能代替CANN编译、真实UB地址空间、寄存器资源、warp同步和NPU性能。SIMD原语模型覆盖分支/尾部、失效tag、空union、容量不足和全hit/全evict。正则同步扫描也不能证明Reg访问与SIMT宏展开后的依赖正确。

新SIMD组合函数在partition写后读、flags生命周期切换处使用公开 `LocalMemBar<VEC_ALL,VEC_ALL>`；核外保留原V_S/S_V交接。[官方LocalMemBar接口](https://asc.gitcode.com/api/SIMD-API/basic_api/reg_vector_compute/sync_control/LocalMemBar.html)说明了其适用流水及参数组合，仍需部署的CANN9.1验证。

本地检查记录：34个新配置各342次冻结ABD逐字段控制流程对照，共11628次；308项原SIMD编号/映射、44项boolean Scan、360项热SIMD压缩原语模型检查。改进inactive Scatter索引后补跑完整ABCDE及全部原语，收敛关闭优化时的控制路径后另补跑control；热压缩CPU原语模型另断言所有lane（包括inactive）的Scatter地址都在已分配范围内。另有77项框架回归与11种构建子集的CPU分发编译链接检查。

LRU必须是物理slot排列，符合现有内核输入契约。探索性注入越界LRU时，冻结ABD本身也被现有miss/LRU oracle拒绝；这种非法输入未计入上述成功用例，也未通过修改golden放行。D不将“不完整LRU”视为合法输入。
