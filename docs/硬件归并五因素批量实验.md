# 硬件归并五因素：一次上机筛选与独立复测

当前已测参考是e82719b的joint_sorted_mrgsort。原sorted_stage.h、sorted_controller.h、带页表ABCDF及其配置保留字节不变。新实验在sorted_sweep_stage.h / sorted_sweep_controller.h，用mask39..69控制五因素的全部31个非空组合；另有mask70..73的4个512线程实验。

| 因素 | 实现 | 需要关注 |
|---|---|---|
| A | 去掉最后一次空refill；单队列直接从输入区去重/映射 | 不省掉正确性和阶段发布；不是简单全局删除同步 |
| B | 32段token值域索引缩小resident二分范围 | 33个边界复用已死的控制区；重复resident的last-owner及全部保护保留；偏斜分布可能收益较小 |
| C | 按实际2/3/4行安排query→uid映射；自适应包长；全部输入装得下时采用MrgSort非耗尽模式 | 仍在参考版预留UB内复用空间，不增大动态UB。MTP1生产尺寸可放下2×2048条完整输入/输出；GM路径仍受独立UB packet预算限制 |
| D | 保留未消费队首，只补新token | 先把剩余input复制到已死output，再从output缓存回填；两阶段隔离防止重叠覆盖。增加UB拷贝和屏障，固定地址热缓存下未必有效 |
| E | 联合阶段256线程，并使用匹配的warp Scan | 原private回退固定1024线程。不能只改launch线程数，否则会丢数据/读到未写warp totals |

31个组合覆盖A、B、AB…ABCDE；另外对C、AC、BCD、ABCD分别编译512线程版本。总计35个新候选，参考ABCDF与当前硬件版各一路，初筛共37路。全部保持相同合法升序TopK、请求身份、初始缓存和状态恢复，不假定resident唯一、不采用近似LRU、不做TopK命中预计算。

C会选择数据布局和包长；D的缓存input/output分割位置在整个请求组内固定且32B对齐，避免活动队列数变化引起缓冲别名。MrgSort队列长度不超过4092；inactive队列不构造越界指针。B的分段表使用ctx[31:64]，只在归并结束后覆盖之前的缓存元数据。每组最大4行，超过后在触碰映射区之前回退。

## 一次启动完成全部流程（逻辑NPU0）

```bash
cd /workspace
git clone --single-branch -b feat/hardware-merge-five-factor https://github.com/liser0019/op_test_kvoffload_simt_echo.git hardware_merge_sweep
cd hardware_merge_sweep
source /usr/local/Ascend/cann-9.1.0/set_env.sh
export PYTHON=/usr/local/python3.11.10/bin/python3
bash scripts/test_hardware_sweep.sh
```

入口为run_hardware_sweep.py，按以下顺序执行，失败立即停止：

1. --sweep-only仅编译参考硬件版和35个新候选的device objects，保留ABCDF基线；每路独立命名，库身份记录构建子集，未编译的mask在prepared构造时拒绝。
2. 专项正确性门禁覆盖冷/热、MTP0/1/3、重复query/resident、可见性、溢出回退、UB/GM、连续状态、输入不变性、保护区及prepared绑定；输入错写尺寸每路重复5次。
3. 默认热场景，固定32请求，MTP0/1/3分别32/64/128行；TopK2048、C4096、max_token262144、seed2026、overlap40。全部37路预热2次、采5样本，每样本完整校验。screen单独保留全部CSV/原始样本。
4. 每个非零MTP工况选择P50最低的前2个新候选，取并集，并始终保留两条参考。MTP0是控制工况，不参与入围排名；它不执行联合优化。
5. 入围名单做新的独立采集：预热10、50样本，复用同库同设备门禁。核对初筛/复测的逻辑输入指纹和库身份。两个阶段的数据分开，不混合统计，也不把初筛赢家称为确认的最优。

输出为新的/workspace/hardware_sweep_*/。主report.md只汇总独立复测，selection.json记录完整初筛排名和入围规则；screen/和confirm/各有capture_metadata.json、report.md、data_index.json和原始CSV。RUN_STATUS.json与根COMPLETE.json都为complete且程序退出0才是完成。失败保留build/gate/screen/confirm日志及现场，不自动删除、不切换输出文件系统。临时目录显式传到全部子进程，空间阈值也传递。

如果只关心部分工况或已有本分支兼容库：

```bash
bash scripts/test_hardware_sweep.sh --scenarios cold_reset full_cache_75pct --top-per-mtp 3
bash scripts/test_hardware_sweep.sh --skip-build --screen-repeat 5 --confirm-repeat 50
```

增加工况/入围数会增加总用时；这次优化的是一次上机能获得的信息量，不承诺35个候选总耗时低于只测3个。可用--implementations明确指定参考和候选子集；两条参考必须保留。输出目录/临时目录和最低余量可用--output/--temp-dir/--min-output-free-bytes等参数控制。不要上传服务器输入、现场、采集或二进制。

## 性能解释与本地验证边界

统一统计精确目标kernel设备Duration，状态恢复、数据排序与tiling上传不计入；每轮交换执行顺序，但5样本不能让37路完全平衡，所以独立复测才用于结论。筛选使用P50，复测报告必须同时看P95、共享/回退及描述符数。MTP0/1选择独立与联合路径涉及持久状态协议转换，不能直接按某轮耗时随意切换。

CPU检查执行真实C++阶段和控制器，硬件MrgSort、事件、LocalTensor使用公开语义模型；模型支持耗尽与完整归并，线程数与Scan warp数匹配，CPU private回退保留原线程数。检查UB/GM、跨批次重复、空/单队列、3队列、严重偏斜、float边界、cache reset及生产尺寸。CPU模型不能验证Bisheng编译、真实256/512/1024线程、DCache、设备事件或性能。

新增的C非耗尽模式与D缓存交接尤其需要真机门禁。本机未执行CANN/NPU；所有候选均为待验证实验，不预先标记最快。向量Squeeze与TopK融合不在这批因素中。
