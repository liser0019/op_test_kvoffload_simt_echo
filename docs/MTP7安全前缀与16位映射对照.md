## 2. A：在归并前确定安全消费量

冻结参考的八行流程是：

```text
加载各行前缀 → 前4路、后4路分别硬件归并 → 再做2路硬件归并
→ 扫描最终输出的 query ID，统计8行各自消费量 → 更新各行游标
```

A 改成：

```text
先看未装完的每行本包末尾 token，取其中最小值 frontier
→ 每行只装入 token <= frontier 的部分，跳过长度为0的源
→ 对选中的前缀完整归并 → 直接按已知长度推进游标
```

为什么安全：升序队列中，未加载元素都不小于本次已经看见的队尾。取所有“尚未装完的源”的最小队尾作为边界，可以保证之后没看见的 token 不会小于本轮输出。相同 token 允许跨包出现，原来的 `lastToken` 和 UID 计数继续处理跨包去重；不能因为读到一个相同 token 就提前结束整行。

已经装完的源不限制 frontier。某些源本轮可能完全没有安全元素，必须从本轮有效列表中移除，不能把长度为 0 的列表传给 `MrgSort`。若本轮仅剩 1／2／4 个有效源，仍推进原来的八行游标，不把请求拆成独立缓存规划。

收益目标是省掉事后消费统计 VF 及其交接。新增前缀二分也有成本，实际补料次数可能变化，因此没有预先承诺 A 一定更快。

## 3. B：压缩临时映射，复用空间扩大归并包

生产尺寸为 TopK2048、capacity4096、八行共16384个 query。冻结版每个 query 用一个 `int32` 保存 UID，共64 KiB。B 用 `uint16` 保存：

- 合法 UID 使用 `0…capacity-1`；`0xffff` 表示无效位置。
- 成功规划仍要求并集不超过 capacity；溢出时照常回退，不能通过截断 UID 掩盖溢出。
- 仅八行、query 总数不超过65408时压缩；这个额外上界还为未激活的向量 lane 保留安全索引。其他组宽或形状使用原32位布局。
- 映射初始化按32位 word分工，每个word只有一个写者，避免两个SIMT线程用读改写更新同一word。
- SIMD生成映射使用B16 `Scatter` 写入16位元素；读取 `current_slots` 和冷收尾时统一解码。没有用32位Scatter伪装成16位写入。

因此映射从64 KiB降为32 KiB，省下32 KiB。**总动态 UB仍为181024 B**，这部分空间用于归并输入、中间结果和输出，单路最大包长从612增加到816条记录。

| 生产8行组布局，单位int32 word | 冻结参考／A | B／AB |
|---|---:|---:|
| query映射 | 16384 | 8192 |
| unique区 | 4096 | 4096 |
| 可复用work区 | 24576 | 32768 |
| 每路包长上限 | 612 | 816 |
| 包所需work上限：40×包长 | 24480 | 32640 |

另有128word控制区及288B Scan区。复用顺序保持“第一半输入失效后承接第二半中间结果”，最终输出与仍活跃的中间结果不重叠。816按8条对齐，使满8路输出适合64条SIMD分块，并为尾块无效lane的索引保留空间；每个四路中间结果最多3264条，未超过硬件列表长度限制。

B没有减少逻辑query数、改变可见性或省略命中查询。目标是减少补料和交接，实际硬件归并轮数仍取决于token分布。

### 16位Scatter的接口依据

[官方Scatter接口](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/910/API/ascendcopapi/docs/en/api/SIMD-API/basic_api/reg_vector_compute/reg_data_store/Scatter_discrete.md)列出了950上的16位目标和16位索引组合。代码利用B32/B16寄存器视图：原B32 lane的低16位处于B16偶数lane；B32有效mask也对应这些偶数lane。奇数lane索引显式分配为互不重复的安全索引，避免无效lane生成重复或越界索引。CPU桩单独检查128个B16索引的唯一性、范围及输出保护区。

[官方掩码约束说明](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/910/programug/Ascendcopdevg/docs/guide/编译与运行/算子编译/约束说明.md)说明不同元素宽度的mask对应关系。CPU桩按该关系模拟；**这不能替代实际Bisheng编译及设备指令验证**。

默认共4实现×2工况×4档MTP×5样本＝**160个正式目标kernel样本**。不展开历史候选、不初筛、不再叠加第二轮50样本。门禁含：已知输入错写回归5次、原有八行边界、前缀极端偏斜／并集4096和4097、10步实际设备状态续用、准备上下文校验，以及每个性能输入的重复审计。性能阶段复用这份门禁，固定初态的参考结果每工况只认证一次，仍逐样本检查输入、完整状态、LRU、逐位置槽位、miss及保护区。
