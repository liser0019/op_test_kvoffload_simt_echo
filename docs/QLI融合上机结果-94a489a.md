# Indexer 与 Plan 融合上机结果（94a489a）

测试日期：2026-11-17。设备：NPU4，Ascend950DT_9582。CANN 9.2.1，torch 2.10.0+cpu，torch_npu 2.10.0.post7。
固定配置：32 请求、TopK 2048、512 线程、共同 QLI S1Base=2；MTP0/1/3/7 容量为 4096/4096/8192/16384。
本轮只报告同设备、同输入链路的完整 Indexer→Plan 设备区间。busy 是目标 kernel 区间并集，span 是首个目标开始至最后一个目标结束；Event 含接口下发。

## 结论

- `joint_mtp7_fused_c_512` 在两档上下文的 16 个工况、20 样本复测中全部通过。
- C 的 256K 冷路径略快，256K 热路径基本持平；100K 的 MTP1/3/7 热路径明显变慢，因此 C 不能作为无条件替代版本。
- A、B 的精确 TopK 门禁发生可重复失败。差异表现为边界处 1 个或少量 token 替换，输出仍有序且有效数量正确；但没有分数证据证明这些 token 等分，因此本轮不把 A/B 纳入性能结论。

## 复现性与构建修复

- split 在 262144/MTP3 冷、热各连续 20 次调用中 TopK 完全一致；C 同工况也完全一致，说明基础 QLI 在该输入上没有观察到随机波动。
- 为在 CANN 9.2.1 编译，生成设备代码把资源偏移改为调用域内联宏，修正四路 GM 输出指针地址空间，并为四个绑定生成独立资源头。
- 运行测试优先装载专用 vendor；恢复 rankpipe 校验分支；修正 profiler 大绝对时间戳的浮点 ulp 容差。
- 完整 CPU 检查：13 项单元测试、绑定/资源门禁、105 次实际 Plan CPU 语义调用均通过。

## 验证边界

- 未测真实模型接受率、Transfer/SFA 或端到端模型吞吐。
- 100K 与 256K 是两个独立上下文输入；同一 MTP 内四路比较使用共同输入，但样本不能外推到所有生产 token 分布。
- A/B 的少量 token 差异可能来自 TopK 边界并列，但本轮没有分数证明，不能据此放行。
