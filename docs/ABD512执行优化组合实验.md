# ABD512 执行优化：四因素与组合测试

本轮以已经在服务器通过六工况验证的 `joint_refine_abd_512` 为共同基础，只改执行方式，固定512线程，保留原1024线程逐行回退。新增16种配置（control、A、B、AB、C、AC、BC、ABC、D、AD、BD、ABD、CD、ACD、BCD、ABCD），另保留ABCDF、bounds、旧ABD、旧BD四条冻结参考，共20路。

**本轮A/B/C/D与旧refine字母不是同一组因素。** 所有新配置始终包含旧refine的A+B+D，不包含旧C。新配置公开ID143..158，名称 `joint_exec_<组合>_512`；无优化control叫 `joint_exec_base_512`。

## 四项实际改动

| 本轮因素 | 实现 | 适用范围 |
|---|---|---|
| A：交错加载 | D的SIMD去重函数对完整64条score/payload记录使用 `Reg::LoadAlign<uint32_t, DIST_DINTLV_B32>` 双搬入，偶数列为score位型、奇数列为原始query位置 | 仅完整64记录且原有对齐成立时启用；不足64记录仍为masked Gather，不能越界读输入。只做位型解释，不把payload数值转为float |
| B：分类投票 | hit、evict分别ballot/popcount得到warp内稳定排名，继续采用原跨warp打包前缀 | 热路径hit/evict分类。保留COUNT_SHIFT=12布局、无效LRU处理、parity和原有block barrier；旧B的boolean miss Scan继续保留 |
| C：单行VF合并 | 实际连续请求组只有1条query时，在一个SIMT VF中执行Phase0及成功后的Phase5 | 保留Phase0重复检测与末尾barrier；检测失败不执行Phase5，由外壳启动原回退。多行保持原控制器，不按CPU侧MTP标签猜组数；UB/GM均支持 |
| D：打包游标 | chunk>=线程数时，按线程步进维护列表号/列内位置，使用加法、比较、减法代替逐记录除法和取模 | 不改变线程分工、packet写入位置、chunk大小和补料批次；小chunk保留原除法/取模索引 |

组合意义：A只作用于执行SIMD去重的路径，旧A单行快路径已跳过该阶段；C主要影响单行；B只影响热分类，冷收尾不会执行；D只影响记录打包。多个因素可能在同一工况下没有同时执行，但仍可能影响编译资源。不能用组合之间的耗时差直接声称每个指令独立占用多少微秒。

未新增完整SIMD热路径Squeeze分类；它属于后续更大改动。本轮B先验证较小的packed ballot Scan替代。没有新线程矩阵、Transfer/SFA或接口端到端实验。

## 源码阅读

- `csrc/joint_variants/exec_options.h`：本轮四开关与旧ABD约束。
- `exec_simd.h`：A；编号、跨64-lane重复和容量溢出逻辑保留旧D。
- `exec_stage.h`：B的 `ExecPackedScan`、D的游标，以及C的Phase6（Phase0+Phase5）。
- `exec_controller.h`：C仅在实际单行组下启动Phase6，失败保持旧回退。
- `joint_variants.py`：名称、ID、元数据；`checks/generate_joint_variants.py`生成互不混淆的kernel符号。
- `checks/check_exec_kernels.py`：CPU模型与UBSan；`checks/check_exec_npu.py`：设备门禁。
- `run_exec_sweep.py`：一键构建、门禁、初筛、独立正式采集与失败保存。

冻结的 `refine_stage.h`、`refine_simd.h`、`refine_controller.h`、`cold_finish.h` 及带页表ABCDF计算源码不改。control用于区分新文件组织与优化本身的影响。新文件是基于冻结文件的独立实验副本，避免用条件修改污染参考路径。

## 服务器一键运行

请使用独立目录，不覆盖之前已验证的源码、库和结果。在已有匹配torch/torch_npu的环境执行，CANN9.1、ascend950、现有 `-O3` 构建选项保持不变。以下选择本轮上一把使用的逻辑卡3，可按服务器可用卡调整。

```bash
source /usr/local/Ascend/cann-9.1.0/set_env.sh
mkdir -p /workspace/single_op_test
cd /workspace/single_op_test
RUN_DIR=$(mktemp -d /workspace/single_op_test/abd_exec_XXXXXX)
git clone --single-branch --branch feat/abd512-execution-sweep \
  https://github.com/liser0019/op_test_kvoffload_simt_echo.git "$RUN_DIR/src"
cd "$RUN_DIR/src"
git rev-parse HEAD | tee "$RUN_DIR/source_commit.txt"
export PYTHON=/usr/local/python3.11.10/bin/python3
bash scripts/test_exec_sweep.sh --device 3 \
  --output "$RUN_DIR/results" --temp-dir "$RUN_DIR/tmp"
```

`source`路径按服务器安装位置调整。输出目录须尚不存在。默认一次执行：

1. `--exec-only` 精简构建本轮新配置和冻结参考，库身份严格检查。
2. 全20路严格正确性门禁，输入错写回归5次，沿用缓存、LRU、逐位置currentSlots、miss、尾部、保护区、连续状态及溢出回退检查；补充63/64/65等SIMD边界。
3. 相同六工况全部20路初筛：warmup2、repeat5。
4. 每个场景/MTP选前2个优化候选，取并集，并始终保留四条冻结参考及control；重新采集warmup10、repeat50。

初筛和复测样本不混合。单行MTP0独立参与排名；不会把各场景赢家拼成一个实现。结果慢也保留，不生成“优化成功”的预设结论。

如需全部20路正式50样本，跳过初筛：

```bash
bash scripts/test_exec_sweep.sh --device 3 --full-confirm \
  --output "$RUN_DIR/all_formal" --temp-dir "$RUN_DIR/tmp"
```

如果已构建当前源码，可加 `--skip-build`，仍不能绕过身份校验。缩小候选范围时需要保留五个参考（含control），例如：

```bash
bash scripts/test_exec_sweep.sh --device 3 --skip-build --full-confirm \
  --implementations abcdf_pages joint_integrated_bounds_512 \
    joint_refine_abd_512 joint_refine_bd_512 joint_exec_base_512 \
    joint_exec_a_512 joint_exec_b_512 joint_exec_c_512 \
    joint_exec_d_512 joint_exec_abcd_512 \
  --output "$RUN_DIR/subset" --temp-dir "$RUN_DIR/tmp"
```

参数 `--describe-only` 只打印配置，不构建、不初始化NPU。

## 口径与结果

保持上一轮逻辑输入：32请求、TopK2048、capacity4096、max_token262144、block_size64、seed2026，MTP0/1/3对应32/64/128条query；cold_reset、full_cache_75pct、共同升序输入与overlap40。75%仍指首行标签，其他行实际miss读取报告；不改变重复token或因果可见性。

每次性能调用前恢复相同初态，逐样本完整校验；连续状态门禁另行直接续用设备写出的状态。状态恢复、TensorMove、CPU校验不计入目标kernel Duration。

继续使用 `kernel_details.csv` 的精确kernel名、Duration(us)、严格样本数和轮换顺序。ACTIVE开始后保留并记录1秒宿主等待。汇总列出P50/P95、数量以及每个实现/ABCDF、/bounds、/ABD、/BD、/control；比值小于1表示更快。

`report.md` 是正式结果；`selection.json` 保留初筛依据。采集子目录的 `capture_metadata.json` 和 `data_index.json` 包含CSV索引、原始样本、miss/descriptor数、输入指纹及设备/库/编译身份。失败立即停止并保存日志与现场，不写成功 COMPLETE.json；只有退出码0、报告和COMPLETE.json齐全才算整轮完成。

运行前检查实际输出和临时目录的空间、inode及可写性，TMPDIR在解析子进程前设置。最低阈值可配置，不是profiling大小预测。不要自动删除旧数据；若显式选择 `/dev/shm`，需要自行转存持久目录。源码、输入、失败现场、二进制和采集文件留在运行机器，不上传GitHub。

## 验证边界

本地执行的是g++ CPU API模型、UBSan、Python/脚本与分发检查；不代表Bisheng编译、地址空间、真实warp同步或性能验证。新API签名依据CANN文档和公开RegBase样例核对，仍需目标CANN9.1编译及NPU门禁确认。C合并VF也可能改变寄存器/编译资源，不能预先保证更快。

API依据：[CANN9.1交错LoadAlign](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/910/API/ascendcopapi/docs/en/api/SIMD-API/basic_api/reg_vector_compute/reg_data_load/LoadAlign_continuous.md)。

本轮本地检查记录：16种配置各324次冻结ABD逐字段控制器对照（共5184次），308项SIMD编号/映射、44项boolean Scan和48项hit/evict packed Scan原语模型检查，68项框架回归，10种生成分发子集的CPU编译链接检查；另做Python语法、shell语法及源码身份检查。Scan原语模型使用256个CPU线程，不是512线程设备执行验证。

同步脚本扫描exec stage/controller/SIMD与原cold_finish，未输出候选；正则数据流分析不能完整识别Reg load/store与SIMT宏的依赖，不能据此证明真实同步正确。
